Why JWTs in 'har' Files & Debug Logs Are Live Session Bombs

  • JWT Payloads Are Base64Url — NOT Encrypted! Anyone reading an unredacted eyJ... token in a Jira/GitHub comment can base64-decode user emails, tenant UUIDs, and role claims in 2 seconds — and replay the bearer token until exp!

  • Consistent Request-Correlation: Distinct JWTs become <JWT_TOKEN_1> and <JWT_TOKEN_2>, so you can still trace multi-user race conditions across 500 log lines!

Frequently Asked Questions

Does redacting inside JSON payloads keep the JSON valid and parseable?

Yes! PasteShield substitutes the secret token inside quotes (e.g. "token": "<JWT_TOKEN_1>") so JSON formatters, linters, and LLMs still parse the structure cleanly.

Why shouldn't I paste even an 'expired' JWT into public issues or AI prompts?

Even expired JWT headers and payloads expose internal user IDs, email addresses, org/tenant IDs, issuer URLs, and key IDs (kid) in plaintext Base64Url.

Can I install this directly inside VS Code or Cursor so I don't even switch tabs?

Yes — PasteShield is available as a lightweight, zero-dependency extension for VS Code and Cursor with instant keyboard shortcuts.
